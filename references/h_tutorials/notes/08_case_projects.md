### 卡片 1 · `cu100-h2o-opt` —— Cu(100)-水界面几何优化

**算什么体系**
Cu(100) 3 层 slab（4×4 表面胞，共 48 Cu）+ 38 个 H₂O，共 **186 原子**
（实测 `coord.inc`：`{'H': 92, 'Cu': 48, 'O': 46}` → O46 + H92 = 38 个 H₂O）。

**任务** `RUN_TYPE GEO_OPT`（`cp2k.inp:119`）。

**关键设置逐项 + 理由**

| 段 | 设置 | 位置 | 理由 / 备注 |
|---|---|---|---|
| `@SET` | `@SET DATAPATH /opt/cp2k/cp2k-6.1/data` | L1 | 用 CP2K 预处理器变量；`${DATAPATH}` 在 L6/L8 被展开 |
| `&DFT` | `BASIS_SET_FILE_NAME ${DATAPATH}/BASIS_MOLOPT` | L6 | MOLOPT 族基组只在 `BASIS_MOLOPT` 里 |
| | `POTENTIAL_FILE_NAME ${DATAPATH}/GTH_POTENTIALS` | L8 | GTH 赝势 |
| | **`UKS T`** | L12 | **自旋极化**。金属 slab + 含时断键，作者选择 UKS 而非 RKS |
| `&MGRID` | `CUTOFF 350` | L15 | Ry；350 是过渡金属软 GTH 的常见生产值（模板默认 300） |
| `&QS` | `WF_INTERPOLATION ASPC` + `EXTRAPOLATION_ORDER 3` | L18–19 | **几何优化也用 ASPC 外推**——虽然优化步间位移大、外推收益不如 MD，但作者统一开了 |
| `&SCF` | `SCF_GUESS RESTART` | L30 | 从 `cp2k-RESTART.wfn` 续波函数 |
| | `EPS_SCF 1.0E-6` | L31 | 优化用 1e-6（比 MD 的 5e-6 更严，因为要算可靠的力） |
| | `MAX_SCF 500` | L32 | |
| | **`ADDED_MOS 500`** | L33 | 给金属/半金属加 500 个空带 —— 与 SMEAR 配套 |
| | **`CHOLESKY INVERSE`** | L34 | 用 Cholesky 求重叠矩阵逆，加速对角化 |
| | `&SMEAR ON` / `FERMI_DIRAC` / `300 K` | L35–38 | Cu d 带在 E_F 处有态密度 → 必须展宽，否则 SCF 振荡 |
| | `&DIAGONALIZATION` `ALGORITHM STANDARD` + **`EPS_ADAPT 0.01`** | L39–42 | **对角化 + DIIS**，不是 OT；`EPS_ADAPT` 自适应收紧 |
| | `&MIXING` `BROYDEN_MIXING` `ALPHA 0.1` `BETA 1.5` `NBROYDEN 8` | L43–48 | α=0.1 偏保守（金属电荷 sloshing），β=1.5 是稳健组合 |
| `&XC` | `PBE` | L51 | 纯 GGA，**没有 DFT-D3**（对比 Au 系工程，见卡片 3） |
| `&PRINT` | `&MULLIKEN SILENT` `FILENAME =Mull.mulliken` `&EACH MD 5` | L55–60 | `=Mull.mulliken` 的 `=` 前缀 = 精确文件名，不带 project 前缀 |
| `&CELL` | `ABC 10.242489 10.242489 21.0` / `ALPHA_BETA_GAMMA 90 90 90` | L72–73 | 正交；a=b=4×2.5606 Å（Cu 晶格 3.615 Å /√2） |
| `&COORD` | `@INCLUDE 'coord.inc'` | L76 | 坐标外置 |
| `&KIND` | C/O/H/Cu/Al/Pt/Pd/Au **八个** KIND，全用 `DZVP-MOLOPT-SR-GTH` | L82–113 | ⚠️ **明显是从别的输入卡抄来的模板**——本体系只含 Cu/O/H，C/Al/Pt/Pd/Au 是死代码。另外 Cu/Al/Pd/Au 四处的关键字拼成 `BaSIS_SET`（大小写混写），CP2K 大小写不敏感所以能跑 |
| `&MOTION` | `&MD` 段虽然存在但 RUN_TYPE 是 GEO_OPT（L125–142） | | 死代码 |
| `&GEO_OPT` | `MAX_ITER 400` `OPTIMIZER LBFGS` `MAX_FORCE 6.0E-4` `&LBFGS MAX_H_RANK 30` | L143–151 | LBFGS + 有限内存秩 30 |
| `&CONSTRAINT` | **`&FIXED_ATOMS LIST 139..170`** | L158–161 | 冻 **32 个原子**（索引 139–170）= **底下 2 层 Cu**（每层 16 个）—— **✅ 本批唯一索引正确的卡** |

### 卡片 2 · `cu100-h2o-aimd` —— Cu(100)-水界面 AIMD（本批唯一有真实产物的 MD）

**算什么体系**
Cu(100) 3 层（48 Cu）+ **28 个 H₂O**，共 **132 原子**（实测 `coord.inc`：
`{'H': 56, 'Cu': 48, 'O': 28}`）。
**注意：与卡片 1 不是同一个体系**——水从 38 个减到 28 个（少 10 个水），
真空层从 21.0 Å 加到 23.0 Å。这是「先小体系 opt 再 MD」的常规流水，不是笔误。

**任务** `RUN_TYPE MD`（`cp2k.inp:121`），`ENSEMBLE NVT`。

**与卡片 1 的差异（逐行 diff）**

| 设置 | 卡片 1 (opt) | 卡片 2 (aimd) | 位置 | 理由 |
|---|---|---|---|---|
| cell c | `21.0` | **`23.0`** | L72 | 水少了但真空加大 → MD 中水面起伏不撞周期像 |
| `EPS_SCF` | `1.0E-6` | **`5.0E-6`** | L31 | MD 每步都要 SCF，放宽 5× 换速度（力仍够用） |
| `RUN_TYPE` | `GEO_OPT` | **`MD`** | L121 | |
| `TEMPERATURE` | `600.0`（死代码） | **`300.0`** | L129 | 室温固液界面 |
| `&PRINT`（`&MOTION` 内） | 无 | **`&TRAJECTORY MD 1` + `&VELOCITIES MD 1` + `&RESTART_HISTORY MD 500`** | L158–174 | 每步存轨迹和速度；每 500 步存一次历史重启 |
| `&FIXED_ATOMS` | `139..170` | `139..170`（同） | L177 | ⚠️ **但本卡只有 132 个原子 —— 这个 LIST 完全越界！** |

其余（`@SET`、`UKS T`、`CUTOFF 350`、`&QS ASPC order 3`、`ADDED_MOS 500`、
`CHOLESKY INVERSE`、`&SMEAR FERMI_DIRAC 300 K`、`&DIAGONALIZATION STANDARD
EPS_ADAPT 0.01`、`&MIXING BROYDEN ALPHA 0.1 BETA 1.5 NBROYDEN 8`、`PBE`、
`&MULLIKEN SILENT /5`、8 个 KIND、`&THERMOSTAT TYPE NOSE + &NOSE LENGTH 3
YOSHIDA 3 MTS 2 TIMECON [wavenumber_t] 1000`）**逐字相同** → 这一整套就是作者的
「固液界面模板」。

#### ⚠️⚠️ `&FIXED_ATOMS LIST 139..170` 越界 —— 本批最严重的隐藏错误

**实测 element block 表**

| 元素 | 行范围 | 个数 |
|---|---|---|
| H | **1 .. 56** | 56 |
| O | **57 .. 84** | 28 |
| Cu | **85 .. 132** | 48 |

**体系总共只有 132 个原子，而 `&FIXED_ATOMS` 请求 139..170 —— 全部越界。**

**正确的「底部两层 Cu」索引是 `85..116`**（Cu z=1.4000 的 16 个在 85–100，
z=3.2106 的 16 个在 101–116）。

**CP2K 的反应（实测 `.out`）**：
- `MD| Constraints activated` 出现在 **L129** → 说明 `&CONSTRAINT` 段**被识别了**。
- 但全文 grep `FIXED|CONSTRAIN|constraint` **只有 3 处**（L129 / L149 / L150），
  **没有任何「fixed atoms」计数或越界警告**。
- `Number of Intramolecular constraints: 0` / `Intermolecular constraints: 0` /
  `Degrees of freedom: 393`（= 132 × 3）→ **自由度没有因冻结而减少**
  （CP2K 的 `&FIXED_ATOMS` 是「每步把力置零」，不计入约束计数）。
- **没有任何 `ERROR` / `ABORT`**，作业照常跑了 2534 步。

**后果**：**这次 MD 实际上没有冻结任何原子。**
被当作「固定基底」的 48 个 Cu 全程自由热运动；而 `coord.inc` 显示 Cu 第 3 层
z 值已经散开成 18 个不同值（4.9878 … 5.0599，**这是从卡片 1 的 opt 结果续下来的
已弛豫结构**），所以 132 原子体系里整块 Cu 都能动。

**为什么会这样**：卡片 2 是从卡片 1 的输入卡改的——**砍掉了 10 个水
（186 → 132 原子）却忘了同步改 `&FIXED_ATOMS` 的索引**。
这是「改体系忘了改索引」的典型事故，而且**CP2K 静默通过**。

> **这直接证明了 ④.2 建议 #14 的必要性**：`validate_inp.py` 应该检查
> `&FIXED_ATOMS` 的最大索引是否超过 `coord.inc` 的行数。

**交叉印证**：把 `.out` 的 2534 步温度序列拿来判读 —— 若 Cu 被真正冻结，
温度涨落应明显小于全自由体系；实测 `TEMPERATURE [K]` min/max =
**179.30 / 369.73 K**（全自由 393 自由度），与「全体系自由」一致。
（这条是旁证，不是主证；主证是索引越界本身。）

**`sub_cp2k` 提交脚本**（103 B，已照抄）

```bash
export PATH=$PATH:/opt/cp2k/cp2k-6.1/exe/local
mpirun -n 56 cp2k.popt cp2k.inp 1>cp2k.out  2>cp2k.err
```

要点：
- **56 个 MPI rank，纯 MPI 无线程**（`.out` L45–46：`Total number of message
  passing processes 56` / `Number of threads for this process 1`）。
- `1>cp2k.out 2>cp2k.err` **分开重定向**——所以 `cp2k.out` 里没有 stderr。
  这一条很关键：本次 MPI 崩溃信息**恰好出现在 `cp2k.out` 尾部**（见 ③），
  说明 Intel MPI 把 `BAD TERMINATION` 写到了 stdout。

| `cp2k.out` | 15 545 031 B | **真实生产 MD 输出，2534 步后 MPI 崩溃**（见 ③） |

这在物理上比「冻底部」更糟：中间被钉死会阻断 slab 的层间弛豫，

**为什么会这样**：`LIST 240..271` 正好是「假设 coord.inc 先排 Au 的话，
Au 的前 32 个」之外的偏移 —— 数值上 `240 = 208 + 32`，
即**恰好错位了整整 2 层**。看起来像是「按某一版 coord.inc 的行序算的索引，
后来 coord.inc 的元素顺序变了（H/O 被移到前面）而没有同步更新索引」。

> **注意**：本工程没有 `.out`，**无法**像卡片 2 那样确认 CP2K 的实际行为；
> 以上是「按 `coord.inc` 实际行序 + `&FIXED_ATOMS` 语义」得出的静态判读。

> `coord.inc` vs `md/coord.inc` 对比（实测）：父目录 Au 层间距恒为整齐的 **2.3544 Å**
> （6 层全部 z 值精确），md/ 目录则变成 `[2.6361, 2.4176, 2.3548, 2.4217, 2.6424]`
> —— **两侧被拉大、中间保持**，这是典型表面弛豫。说明 `md/coord.inc` 是
> 从某轮弛豫/MD 续下来的结构。

### 2.2 几何层：怎么定 cell、真空、层数

**（a）面内尺寸 = 表面胞整数倍，一个 Å 都不多**

实测证据：
- Cu(100)：`a = b = 10.242489 Å`。Cu 晶格常数 3.615 Å；Cu(100) 面内最近邻 = 3.615/√2
  = 2.5562 Å。**4 × 2.560622 = 10.242488** —— 与输入卡的 `10.242489` 吻合到 1e-6。
  → **4×4 表面胞，没有额外留白。**
- Au(111)：`a = b = 11.738 Å`，γ=120°。**已实测闭合（原先标"无法完全闭合"，现已算清）**：
  - 从 `coord.inc` 的 96 个 Au 里取**同一层**（z 完全相同）算最近邻距离，得

    **立方晶格常数 a₀**；fcc(111) 的**面内**最近邻是 `a₀/√2 = 2.8835 Å`（4.078 那个数
    是立方胞的棱长，不是面内原子间距）。

    即**纵向与体相一致、横向比体相大约 1.8%**。这可能是建模时用的横向晶格常数偏大、
    也可能是有意加了面内应变 —— **仅凭 `coord.inc` 无法区分**，故只登记这两个实测数，
    不推断原因。

  与 `coord.inc` 里 O 的规整格子间距**精确对应** → **整数倍扩胞**。

### 2.3 电子层：可以照搬的整套

&END QS
&SCF

| 赝势 | `GTH-PBE-q<n>`，n = 价电子数（H1 O6 Cu11 Au11 Na9 Ti12） | | ✅ 可照搬 |
| `UKS T` | 自旋极化 | 7/7 张卡都有 | ❌ **不要盲目照搬**：闭壳层体系（纯水、d¹⁰ 金属）用 UKS 白花一倍机时。作者是「一律开」 |

### 2.4 动力学层：`ENSEMBLE` / `STEPS` / `TIMESTEP` / `TEMPERATURE` / `&THERMOSTAT`

**「死代码」现象 —— 这是本批最重要的观察之一**

**7 张卡全部**在 `&MOTION` 里**同时**保留 `&MD` 和 `&GEO_OPT` 两段，
用 `RUN_TYPE` 选哪个生效，另一段整个是死代码：

| 卡 | `RUN_TYPE` | `&MD` 段 | `&GEO_OPT` 段 |
|---|---|---|---|
| cu100-h2o-opt | `GEO_OPT` | **死码**（`STEPS 5000` `TIMESTEP 0.5` `TEMPERATURE 600`） | 生效（LBFGS） |
| cu100-h2o-aimd | `MD` | 生效（300 K） | **死码** |
| au111-h2o | `GEO_OPT` | **死码**（600 K） | 生效（BFGS） |
| au111-h2o/md | `MD` | 生效（330 K） | **整段删除** |
| au111-6Na | `GEO_OPT` | **死码**（600 K） | 生效（BFGS） |
| au111-6Na/md | `MD` | 生效（330 K） | **整段删除** |
| TiO2-Au20 | `MD` | 生效（600 K） | **死码**（LBFGS） |

⚠️ **陷阱**：opt 卡里那个 `TEMPERATURE 600.0` / `TIMESTEP 0.5` / `STEPS 5000`
**根本不生效**。若有人只看 `&MD` 段就以为「作者用 600 K」，会读错。
**`RUN_TYPE` 才是判据。**

**`STEPS` × `TIMESTEP` = 目标时长**

| 卡 | STEPS | TIMESTEP | 目标时长 |
|---|---|---|---|
| cu100-h2o-aimd | 5 000 | 0.5 fs | **2.5 ps** |
| au111-h2o/md | 100 000 | 0.5 fs | **50 ps** |
| au111-6Na/md | 100 000 | 0.5 fs | **50 ps** |
| TiO2-Au20 | 100 000 | 2 fs | **200 ps** |

（`cu100-h2o-opt` 的 `STEPS 5000` 是死码。）

**`TIMESTEP`**：
- 5/7 张卡 = **0.5 fs**（含水体系的标准选择：O–H 伸缩 ~3300 cm⁻¹ → 周期 ~10 fs，
  0.5 fs 给足 20 点/周期）。
- **TiO2-Au20 = 2 fs**，靠 **`&KIND Au MASS 19.7` 把 Au 质量人为降到 1/10**
  把 Au 的振动频率抬高 √10 ≈ 3.16 倍，才敢用 2 fs。
  ⚠️ **代价：动力学不再是真实的**（频率、扩散、声子都被改写）。
  这只适合「结构演化 / 退火 / 团簇烧结」类问题，不适合算动力学量。

**`TEMPERATURE`**：300 K（Cu 水）→ 330 K（Au 水）→ 600 K（TiO₂/Au₂₀）。
单调升高的解释：体系越大、越「硬」（氧化物），越需要高温在有限 ps 内跨越能垒。

**`&THERMOSTAT` —— 7 张卡逐字相同，且 `TIMECON` 的单位方括号是重点**

# REGION MASSIVE                 <- 注释掉的备选
  &NOSE
    LENGTH 3
    YOSHIDA 3
    MTS 2
    TIMECON [wavenumber_t] 1000

**`TIMECON [wavenumber_t] 1000` 到底是什么值 —— 有实测证据**

`cu100-h2o-aimd/cp2k.out` 第 159–167 行（`THERMOSTAT| Thermostat Info for PARTICLES`）：

```
THERMOSTAT| Thermostat Info for PARTICLES
THERMOSTAT| Type of thermostat                               Nose-Hoover-Chains
THERMOSTAT| Nose-Hoover-Chain length                                          3
THERMOSTAT| Nose-Hoover-Chain time constant [  fs]                        33.36

→ **`TIMECON [wavenumber_t] 1000` ⇒ CP2K 打印 `33.36 fs`。**

- 这同时**证实了 `LENGTH 3` / `YOSHIDA 3` / `MTS 2` 都真的生效**（三行输出分别对应）。

### 2.5 输出与约束

**`&MOTION &PRINT`（3 张 MD 卡完全一致）**

```
&PRINT
 &TRAJECTORY
   &EACH
     MD 1
   &END EACH
 &END TRAJECTORY
 &VELOCITIES
   &EACH
     MD 1
   &END EACH
 &END VELOCITIES
 &RESTART_HISTORY
   &EACH
     MD 500
   &END EACH
 &END RESTART_HISTORY
&END PRINT
```

- **轨迹 + 速度都每 1 步打** → `cp2k-pos-1.xyz` 与 `cp2k-vel-1.xyz` 帧数 = 步数 + 1。
  实测印证：`cp2k-pos-1.xyz` 有 **2535 帧**，MD 记录 **2534 步** → 2535 = 2534 + 1 ✔
- **`&RESTART_HISTORY` 每 500 步** → 长 MD 有多个历史重启点，崩了能回退。
- ⚠️ **没有 `&RESTART`**（即没有 `cp2k-1.restart` 每步覆写）。
  这一条在崩溃时的代价见 ③ —— 崩溃后只能靠 `RESTART_HISTORY` 或 `.wfn`。
  `.out` L136 也确认了：`MD| Dump  20  cp2k-1.restart`（CP2K 默认每 20 步 dump）。

**`&DFT &PRINT`**

```
&PRINT
 &MULLIKEN  SILENT
   FILENAME =Mull.mulliken
   &EACH
     MD               5
   &END EACH
 &END MULLIKEN
&END PRINT

3. 取被冻索引对应的**元素与 z 坐标**，看是否 = 「slab 底层金属层」。

### 4.3 三条「抄卡铁律」（建议写进 playbook）

从本批真实卡里提炼出的、会**静默出错**的三条：

1. **`TIMECON` 必须连单位方括号一起抄。**
   `TIMECON [wavenumber_t] 1000` = **33.36 fs**（实测 `.out` L162）；
   `TIMECON 1000` = **1000 fs**。**差 30 倍**，且 CP2K 不报错。

2. **`&FIXED_ATOMS` 的索引必须对照 `coord.inc` 逐行核实；改体系后必须重算。
   错位的索引 CP2K 不会报错，会静默跑出一个物理上错误的轨迹。**

   **本批 5 张卡里 4 张错**（全部为实测）：

   | 卡 | 写的 LIST | 实际效果 |
   |---|---|---|
   | `cu100-h2o-aimd` | `139..170` | **体系只有 132 个原子 → 越界 → 一个原子都没冻住**。`.out` 里 `MD\| Constraints activated`（L129）照常打印，**没有任何警告**，作业跑满 2534 步 |
   | `au111-h2o`（geo + md） | `240..271` | `coord.inc` 里 Au 是 **208..303**（6 层 × 16）。240..271 = **Au 第 3、4 层（slab 正中间）**；底部两层 `208..239` 全程自由 |
   | `au111-h2o-6Na`（geo + md） | `246..277` | Au 变成 **214..309**（Na 插在 O 与 Au 之间）。作者把 240..271 **正确地 +6** 平移成 246..277，但基准本身是错的 → 平移后仍指向第 3、4 层；正确应为 `214..245` |

   **正确范例**：`cu100-h2o-opt` 的 `139..170`（H 1–92 / O 93–138 / Cu 139–186，
   Cu 三层 z=1.4/3.2106/5.0213 → 139..170 恰为底部两层）✔；
   `TiO2-Au20` 的 `1..54`（54 个 O，z ≤ 1.2682）+ `289..324`（36 个 Ti，z = 1.2682）✔。

   **推论**：`&FIXED_ATOMS` 是这类输入卡里**最容易错、也最难发现**的部分，
   因为语法永远合法。**必须在改完坐标后重新核对**；工具的 ④.2#14 建议正是为此。

3. **`RUN_TYPE` 才是判据，`&MOTION` 里另一个段可能是死代码。**
   7/7 张卡都同时留着 `&MD` 和 `&GEO_OPT`。`cu100-h2o-opt` 的
   `TEMPERATURE 600.0` / `TIMESTEP 0.5` / `STEPS 5000` **全都不生效**。
