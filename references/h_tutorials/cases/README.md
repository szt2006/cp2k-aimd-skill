# `cases/` — 真实生产算例（H 层）

这里放**真实跑过的 CP2K 生产项目**的输入卡原文与提交脚本，来源是
`庚子计算整理-cp2k资料-持续更新` 下的 6 个工程目录（Cu(100)/H₂O、Au(111)/H₂O、
Au(111)/H₂O+6Na、TiO₂/Au₂₀ 等，132–452 原子，AIMD 与几何优化）。

它们是 H 层最"接地气"的部分：`examples/` 里那 5 个是 2–8 原子的教学例子，
**全仓库此前一个真实 `.out` 都没有**；这批卡有真实的 `.out`（15.5 MB）、轨迹
（2535 帧 / 21 MB）、提交脚本，以及**真实失败样本**（被调度器 kill 的作业）。

> **逐工程的配方卡与逐行拆解**在 [`../notes/08_case_projects.md`](../notes/08_case_projects.md)。

## ⚠️ 先读这一节：**这批卡有已知错误，照抄会中招**

### `&FIXED_ATOMS` 的索引有 4/5 是错的，而 **CP2K 完全不报错**

这是本批材料**最重要的教训**：冻错原子（甚至全越界、一个都没冻）**CP2K 照样跑完**，
只是物理全错。逐条核验结果：

| 工程 | 卡里写的 `LIST` | 体系原子数 | 实际效果 |
|---|---|---|---|
| `cu100-h2o-aimd` | `139..170` | **132** | ❌ **全部越界 → 一个原子都没冻**，而 `.out` 照常打印 `MD\| Constraints activated`、零警告、跑满 2534 步 |
| `au111-h2o` | `240..271` | 303 | ❌ 冻的是 Au slab 的**正中间两层**（见下），**底部两层反而自由** |
| `au111-h2o-6Na` | `246..277` | 309 | ❌ 把上面那个错基准"正确地 +6 平移"了 → 错误被忠实传播 |
| `cu100-h2o-opt` | `139..170` | 186 | ✅ 合法（这是 AIMD 卡的来源；AIMD 砍了水却忘改索引） |
| `TiO2-Au20` | `1..54` + `289..324` | 452 | ✅ 合法 |

**CP2K 不只是"不报错"，它还会主动告诉你约束生效了。** 实测 `cu100-h2o-aimd/cp2k.out`
（14.8 MB）里的计数：

| 在 `.out` 里 grep | 次数 |
|---|---|
| `MD\| Constraints activated` | **18** |
| `BAD TERMINATION` / `EXIT CODE` | 2 / 2（作业被 kill，见下） |
| `PROGRAM ENDED` | **0** |
| `ENERGY\|` | 2535 |

也就是说：**索引全部越界、一个原子都没冻，而 `.out` 里"约束已激活"打印了 18 次。**
除了回坐标文件逐行数，没有任何输出能提示你冻错了。这就是为什么我们把它做成了一条
**校验器规则**（`validate_inp.py` 会展开 `@INCLUDE` 后比对 `LIST` 与原子数）。

**Au(111) 那条是怎么核实的**（可复现）：把 `au111-h2o/coord.inc` 的 96 个 Au 按 z 聚类，
得到 **6 个平整原子层、每层 16 个**：

```
第1层  z=-5.784  原子序号 208..223   ← 真正的底层
第2层  z=-3.430  原子序号 224..239
第3层  z=-1.076  原子序号 240..255   ┐ 卡里冻的
第4层  z=+1.279  原子序号 256..271   ┘ 是这两层（板正中）
第5层  z=+3.634  原子序号 272..287
第6层  z=+5.989  原子序号 288..303   ← 最顶层
```

⇒ 想冻"底部两层"应当写 `208..239`。

**怎么自己核**（别按元素分块推，一定从坐标文件**逐行数**）：

```bash
# 数坐标文件里的原子数
grep -cE '^\s*[A-Z][a-z]?\s+[-0-9]' coord.inc
# 或直接让校验器查（它会展开 @INCLUDE 并比对 LIST）
python scripts/validate_inp.py <你的卡>.inp
```

**若你从别人的卡改体系**（删/加水、加吸附物、换超胞）：
**必须重算 `&FIXED_ATOMS` 的索引**。`au111-h2o-6Na` 就是"平移得对、但基准本身错"的实例，
说明"认真改"也救不了错基准 —— 只能回坐标文件重数。

### 另一个静默错误：作业被 kill 了，`diagnose.py` 却说没事

`cu100-h2o-aimd/cp2k.out` **没有 `PROGRAM ENDED`**，尾部是 Intel MPI 的清理信息，
全文有 `BAD TERMINATION OF ONE OF YOUR APPLICATION PROCESSES` 与 `EXIT CODE: 15`
（SIGTERM，多半被调度器的墙钟限制杀掉）。输入请求 5000 步，实际只跑了 **2534 步
（1267.0 fs）= 50.68%**。

⚠️ 但旧版 `diagnose.py` 只报"SCF 未收敛 6 次"，**完全没提作业被 kill、也没算完成度** ——
这是最容易误判的一类：用户会以为算完了，拿半条轨迹去算物性。
（已修为识别 `BAD TERMINATION` / `EXIT CODE` / `PROGRAM ENDED` 并给出完成度与续算处方。）

### 第三个静默错误：`&MOTION` 里留着不生效的段

7/7 张卡都在 `&MOTION` 里**同时**留着 `&MD` 和 `&GEO_OPT`。**只有与 `RUN_TYPE`
匹配的那一段生效，另一段是死代码。** 例如 `cu100-h2o-opt` 的
`TEMPERATURE 600.0` / `TIMESTEP 0.5` / `STEPS 5000` **全都不生效**（它是 `RUN_TYPE GEO_OPT`）。
读卡时**先看 `RUN_TYPE`**，别被另一段误导。

### `TIMECON` 必须连单位方括号一起抄

7/7 张卡写 `TIMECON [wavenumber_t] 1000`，`.out` 打印
`Nose-Hoover-Chain time constant [  fs] 33.36`。

| 写法 | 实际时长 |
|---|---|
| `TIMECON [wavenumber_t] 1000` | **33.36 fs** |
| `TIMECON 1000`（省略单位，默认 fs） | **1000 fs** |

**差 30 倍**，且 CP2K 不报错。换算关系：`t[fs] = 33356.40952 / ν̃[cm⁻¹]`。

## 打包约定（为什么有些文件是"摘录"）

| 文件 | 内容 |
|---|---|
| `*_cp2k.inp`、`*_sub_cp2k.txt` | **原文照抄**（逐字节，仅换行符归一化） |
| `*_coord.head10tail5.txt`、`*_Layer*.head10tail5.txt` | **前 10 行 + 后 5 行摘录** |
| `_COPY_MANIFEST.tsv` | 逐文件登记源路径、字节数、sha256 |

**大文件不入库**：`cp2k.out`（1.1–15.5 MB）与 `cp2k-pos-1.xyz`（1.8–21.9 MB）
只登记 sha256 与行数，不复制。坐标文件动辄 300+ 行，只存摘录；但清单里
**同时登记源文件的完整行数与字节数**（如 `head10+tail5 excerpt (303 lines / 9205 bytes)`），
所以你能一眼看出被截了多少。

### 因此 `@INCLUDE 'coord.inc'` 在本地解析不了

这些卡用 `@INCLUDE 'coord.inc'` 引用坐标，而 `coord.inc` 只有摘录、**不在本目录**。
跑 `validate_inp.py` 会如实报"找不到 `@INCLUDE` 的文件"—— **这是打包方式的必然结果，
不是卡有问题**。要真跑，请从源目录取完整 `coord.inc`。

（也正因如此，"数原子数去核对 `&FIXED_ATOMS`"这件事在这些卡上无法就地完成 ——
上表里 `cu100-h2o-aimd` 的 132 个原子是从源的完整 `coord.inc` 数出来的。）

## 溯源可验证

清单里的 sha256 **有工具独立重算**（不信任清单本身）：

```bash
python _verify_case_provenance.py          # 副本与源文件都重算 sha256
python _verify_case_provenance.py --json
```

它验三件事：① 副本没被改过；② 清单里的**源** sha256 没记错；③ 截断件必须如实标注为 excerpt。
当前 **17/17 一致**。源目录不可用时（别人只拿到 skill 副本），脚本会退化为只验副本自身
一致性，并**明确说"来源未验证"**——不会假装验过了。
