## 0. 为什么单独一个文件

上一轮 G 层把"关键字默认值"分散在各专题文件里，但**输入文件本身的语法规则**（注释符、续行、单位方括号、逻辑值、section 默认参数）和**输出控制机制**（printkey / 迭代层级 / EACH / ADD_LAST / FILENAME）一直没有系统整理。

这两块是**每天都在用、但官方文档很分散**的内容。本文件把它们集中。

> **权威性提示**：官方在本页明确写道——
> **"The documentation generated by the executable is always consistent with its version, whereas the one on the website refers to the latest version."**
> 即：**用 `cp2k --html` / `--xml` 生成的文档永远和你手上这个二进制版本一致**，而网站手册永远对应最新版。这是排查"为什么这个关键字不认"的第一手段。

## 1. 输入文件的基本结构

官方原文（`input_file` 页）：

> The basic idea of the input is to define the options for the method that you want to use to calculate the forces/energy in the `FORCE_EVAL` section. If you use the ab-initio DFT part then the `DFT` and `QS` subsections will probabily of interest for you. The method to use is choosen with `FORCE_EVAL%METHOD` keyword, i.e. the keyword `METHOD` in the `FORCE_EVAL` section. So you can easily switch from one method to the another if you gave meaningful parameters to both.
>
> Then parameters for the kind of calculation (run type) to do using that method (energy,force,molecular dynamics,langevin,…) are defined in the `MOTION` section
>
> Finally in the `GLOBAL` section you can choose the run type to perform with the keyword `RUN_TYPE`, the name of the project (`PROJECT`), used to generate most of the output files, the `PRINT_LEVEL` keyword that controls the general level of output, and other general flags. The `GLOBAL%PRINT%PHYSCON` keyword enables a printout of the physical constants used by cp2k.

### 1.1 三大段职责（官方口径）

| 段 | 职责 | 关键内容 |
|---|---|---|
| `&FORCE_EVAL` | **用什么方法**算能量/力 | `METHOD` 切换方法（QUICKSTEP / FIST / QMMM / …）；DFT 时看 `&DFT` + `&QS` |
| `&MOTION` | **做什么类型的计算** | 能量 / 力 / MD / Langevin / 优化 … |
| `&GLOBAL` | **总控** | `RUN_TYPE`（运行类型）、`PROJECT`（输出文件前缀）、`PRINT_LEVEL`（总输出级别）、其它通用开关 |

**设计意图**（官方原文隐含）：方法参数与运行类型**解耦**——只要两边都给好了参数，就能"轻易地从一种方法切到另一种"。

**实用推论**：`RUN_TYPE ENERGY` → `GEO_OPT` → `MD` 的切换**不需要改 `&FORCE_EVAL`**，只改 `&GLOBAL/RUN_TYPE` 并加上 `&MOTION` 对应段。这正是"先静态算一版，再拿去优化"的标准做法。

### 1.2 额外有用开关

| 关键字 | 作用 |
|---|---|
| `GLOBAL%PRINT_LEVEL` | 控制**总体**输出详细程度 |
| `GLOBAL%PRINT%PHYSCON` | 打印 CP2K 使用的**物理常数**（换算时有用） |

## 2. 输入语法规则（官方逐条）

官方原文（`input_file` 页 "Input Syntax" 节），逐条对应：

| # | 官方原文 | 规则 |
|---|---|---|
| 1 | "the input is subdivided in sections that start with "&" and end with "&END"" | **段**以 `&` 开始、`&END` 结束 |
| 2 | "each section can contain other sections and keywords followed by values" | 段可嵌套段与关键字（关键字后跟值） |
| 3 | "both the section names and the keyword names are case insensitive" | **段名与关键字名大小写不敏感** |
| 4 | "the special characters "#" and "!" denote the beginning of a comment that goes until the end of the line" | `#` 与 `!` **都**是注释起始符，注释到行尾 |
| 5 | "If the value of the keyword is experssed in units, perceding the value by the units in square bracket changes them. In the square brackets the units should have no space. For example "[m]" switches to meters." | **方括号内写单位可改变单位**；方括号内**不能有空格** |
| 6 | "A long line of input can be split using the "\" character at the end of the line" | 长行可用**行尾 `\`** 续行 |
| 7 | "keywords with a logical value (flags), often have a value that is false when the keyword is missing; the value true when one writes just the keyword (lone_keyword_value), or they can be given an explicit value after the keyword as normal (for example `KEYWORD FALSE`)." | **逻辑值三态**：不写 = 假；只写关键字 = 真；显式写值 = 按值 |
| 8 | "Sections can have a default parameter that comes right after the section value. For example the `OT` section has a logical default parameter that controls the activation of the OT method." | **段可以有默认参数**（写在段名后） |

### 2.1 逻辑值三态（最容易出错，官方举例）

官方给的 OT 例子：

```
&OT
...
&END OT
```
→ **激活** OT 方法

```
&OT FALSE
...
&END OT
```
→ **关闭** OT 方法（"or the absence of the OT section"——或者干脆不写这个段）

**要点**：
- 只写 `&OT` 就**等于开启**（因为段默认参数是逻辑真）。
- 写 `&OT FALSE` 或**整个段不写**，效果相同（都是关闭）。
- 单个关键字同理：`PRINT_LEVEL` 这类带值的必须写值；`CENTER_COORDINATES T` 这类可写 `T`/`F`，也可只写关键字名。

### 2.2 单位方括号（官方示例）

官方原文只给了一个例子：`[m]` 切换到米。

**G 层从官方各处示例归纳的实际用法**（均为官方示例中出现过的写法）：

```
TIMESTEP [fs] 0.5
TARGET [angstrom] 2.0
TARGET_GROWTH [angstrom*fs^-1] 0.0008
CONVERGENCE [eV] 1.0e-7
ABC [angstrom] 14.0 14.0 14.0
INTENSITY 4.08E+13          ! 单位由上下文（EFIELD）决定
```

**注意**：方括号内**不能有空格**（官方明确）。`[angstrom*fs^-1]` 这种复合单位是官方示例中的写法。

### 2.3 注释符（`#` 与 `!`）

两者等价，都注释到行尾。官方示例里两种都出现过：

```
! this is 529 eV:
WAVELENGTH 2.34374655955
# 或者
PROJECT my_geo_opt   # 行内注释
```

**实用技巧**（G 层归纳，非官方原文）：官方示例中常见用 `#`/`!` **成对注释掉整段**，例如 TDDFT 页把可选的 `&XC` / `&MGRID` 段注释掉。这比删除更安全。

## 3. 输出控制：printkey 机制（官方 `printkey` 页）

官方原文：

> To control the output of information or properties often *printkeys* are used. A printkey is a section that has a default value that says at which print level to start printing the corresponding values, and keywords to control their output. Normally printkeys are kept together in a `PRINT` section.

### 3.1 迭代层级（iteration level）——理解 printkey 的前提

官方原文：

> During the calculations cp2k keeps a global iteration level which is a set of integers that keep track which iteration one is doing at that moment.
>
> The exact meaning of each iteration level depends on the run type, for example doing an MD with the QS GPW method an iteration level of **1_4_5** means that the program is doing the **5th scf step of the 4th md step**, whereas **1_9** means the we are at the **9th md step (outside the scf loop)**. The first 1 is a **root iteration level that stays always 1 during a normal md run**.

**归纳**：

| 层级串 | 含义（QS-GPW MD） |
|---|---|
| `1_4_5` | 第 4 个 MD 步内的第 5 个 SCF 步 |
| `1_9` | 第 9 个 MD 步（**在 SCF 循环之外**） |
| 首位 `1` | 根层级，正常 MD 运行期间恒为 1 |

> **实用推论**：写 `&EACH` 时要先想清楚"我要的是 MD 步粒度还是 SCF 步粒度"。`1_9` 这种位数少的，表示它在较外层。

### 3.2 printkey 的四个控制项（官方逐条）

#### (1) 段参数：起始打印级别

官方原文：

> section parameter: Level starting at which this property is printed, valid values are `ON, OFF, SILENT, LOW, MEDIUM, HIGH, DEBUG`. No section means the default value, the presence of the prind sections implies a value of `ON` (always printed), if one wants to selectively switch off the printkey it is possible the give it the explicit value OFF, i.e. `&SECTION OFF`

| 取值 | 含义 |
|---|---|
| `ON` | 总是打印 |
| `OFF` | 关闭 |
| `SILENT` / `LOW` / `MEDIUM` / `HIGH` / `DEBUG` | 按级别递增 |

**行为规则**：
- **不写该段** → 用默认值（默认值决定了"从哪个级别开始打印"）。
- **写了段但不给参数** → 隐含 `ON`（总是打印）。
- **想单独关掉** → `&SECTION OFF`。

#### (2) `EACH`：多久打印一次

官方原文：

> `EACH`: How often this proprety is printed, this is matched with the actual iteration level from the right replacing non present levels with 1. For example "2 1" for an scf property during an scf means to write each scf step each 2 md step. How to handle the last iteration is treated separately in ADD_LAST (this mean that EACH 0 might print the last iteration)

**关键机制**：`EACH` 的数值**从右往左**与迭代层级匹配，**缺失的层级按 1 处理**。

举例：`EACH 2 1` 用于 SCF 属性时 = **每 2 个 MD 步写一次，每次 MD 步内每 1 个 SCF 步都写**。

#### (3) `ADD_LAST`：最后一步怎么处理

官方原文：

> `ADD_LAST`: If the last iteration should be added, and if it should be marked symbolically (with l) or with the iteration number. Not every process is able to identify the last iteration early enough to be able to output. Valid keywords: NO, NUMERIC, SYMBOLIC

| 取值 | 含义 |
|---|---|
| `NO` | 不加最后一步 |
| `NUMERIC` | 用**迭代号**标记 |
| `SYMBOLIC` | 用符号 `l` 标记 |

**官方警告**：并非每个过程都能足够早地识别"最后一步"，因此不能保证一定输出。

#### (4) `COMMON_ITERATION_LEVELS`：多少个迭代层级共用一个文件

官方原文：

> `COMMON_ITERATION_LEVELS`: How many iterations levels should be written in the same file (no extra information about the actual iteration level is written to the file). If it is 0 then all iterations go to different files, if it is 1 then (if the current property is an SCF property and one is doing an MD then each MD step goes to a separate file (but different scf steps are in the same file)

| 取值 | 行为 |
|---|---|
| `0` | **所有迭代各写各的文件** |
| `1` | SCF 属性做 MD 时：**每个 MD 步一个文件**，但同一步内不同 SCF 步写在同一文件 |

> **陷阱**：`COMMON_ITERATION_LEVELS 0` 会**产生大量文件**。G 层在 `07_restarting.md` 的 `&PRINT/&RESTART` 示例中见过官方用 `COMMON_ITERATION_LEVELS 1`——这是有意的。

#### (5) `FILENAME`：文件名控制（官方逐条，很关键）

官方原文：

> - Use `STD_OUT` (exactly as written here) for the screen or standard logger.
> - Use "filename" to get "projectname-filename[-middlename]-iteration.extension"
> - Use "./filename" (or any path that contains at least one "/") to get "./filename[-middlename]-iteration.extension"
> - Use "=filename" to get exactly filename as output file (please note that this can be dangerous because different output/iterations might write on the same file

| 写法 | 得到什么 |
|---|---|
| `STD_OUT` | 屏幕/标准 logger（**必须精确这样写**） |
| `filename` | `项目名-filename[-中间名]-迭代号.扩展名` |
| `./filename`（或任何含 `/` 的路径） | `./filename[-中间名]-迭代号.扩展名`（**不带项目名前缀**） |
| `=filename` | **精确就是 filename** —— 官方警告：**危险**，不同输出/迭代可能写到同一文件 |

> **实用要点**：想让文件落在**当前目录且不带项目名前缀**，就写 `./name`；想写进子目录，路径里带 `/` 即可。想彻底固定文件名用 `=name`，但要清楚会互相覆盖。

## 4. 生成与当前版本一致的文档（官方推荐）

官方原文（`input_file` 页开头）：

> Documentation of cp2k can be found on the website [http://manual.cp2k.org](http://manual.cp2k.org) and can also be generated by the cp2k executable itself using the flag `–html` or `–xml` (followed by xml2htm if you want an html documentation). The documentation generated by the executable is always consistent with its version, whereas the one on the website refers to the latest version.

| 方式 | 命令 | 特点 |
|---|---|---|
| 网站手册 | <https://manual.cp2k.org> | 永远对应**最新版** |
| 可执行文件生成 | `cp2k --html` | **与你的二进制版本一致** |
| 可执行文件生成 XML | `cp2k --xml`（再用 `xml2htm` 转 HTML） | 同上，可程序化处理 |

> **这是排查关键字问题最可靠的一招**：手册说有这么个关键字但你的 CP2K 不认 → 大概率是**手册对应新版、你的二进制是旧版**。用 `cp2k --html` 生成本地文档比对。

**G 层相关交叉印证**：`11_version_changelog.md` §2 记录了各版本移除/改名的关键字（如 2026.2 移除 `&CELL_OPT/TYPE`），与此机制互相印证。

## 6. 常见语法坑（G 层从官方示例归纳）

| 坑 | 表现 | 官方依据/处置 |
|---|---|---|
| 方括号里有空格 | `[angstrom * fs^-1]` 不生效 | 官方明确"units should have no space" |
| 以为 `#` 不能注释 | 只用 `!` | 官方明确两者都可 |
| 段名/关键字名大小写 | 担心写错 | 官方明确大小写不敏感 |
| 逻辑值以为必须写 `T` | 写了 `&OT` 却担心没开 | 只写段名即等于真 |
| `&OT FALSE` 与不写段 | 以为不同 | 官方明确效果相同 |
| `COMMON_ITERATION_LEVELS 0` | 目录里文件爆炸 | 官方说明 0 = 每迭代一个文件 |
| `=filename` | 文件互相覆盖 | 官方明确警告 dangerous |
| `EACH` 方向搞反 | 打印频率不对 | 官方说明"从右往左匹配，缺失按 1" |
| 手册关键字不被识别 | 报未知关键字 | 用 `cp2k --html` 生成本版本文档比对 |

## 7. 编码约定消息（`conv` 页，面向开发者）

<https://www.cp2k.org/conv> 列出 CP2K 源码的**编码约定检查消息**（c001–c205），例如：

| 编号 | 消息 | 要求 |
|---|---|---|
| c001 | Found `${statement}` with unchecked STAT | 检查 `STAT=` |
| c002 | Module `${mod}` USEd without ONLY clause or not PRIVATE | 模块开头加 `PRIVATE` |
| c003 | Symbol `${var}` is IMPLICIT-SAVE | 移初始化到 routine body 或显式 `SAVE` |
| c004 | Symbol `${var}` is IMPLICIT-TYPE | 模块加 `IMPLICIT NONE` |
| c005 | Symbol `${var}` is THREADPRIVATE | 不用 thread-private 变量 |
| c006 | OMP PARALLEL without DEFAULT(NONE) | 加 `DEFAULT(NONE)` |
| c012 | WRITE with hardcoded unit | 用 printkey，别直接写 stdout |
| c101 | CALL cp_fm_gemm | 用 `parallel_gemm`（可切 ScaLAPACK/COSMA） |
| c102/c103/c205 | CALL m_abort / mp_abort / STOP | 用 `CPABORT("message")` |
| c107 | CALL GET_ENVIRONMENT_VARIABLE | 不用环境变量控制计算（伤可复现性），改用输入关键字 |
| c201 | GOTO | 不用 |
| c202 | FORALL | 不用（Fortran 2018 起弃用） |

**对使用者的价值**：
- **c107 这条对使用者同样有意义**——官方明确"不用环境变量控制计算，因为伤害可复现性，改用输入关键字"。这解释了为什么 CP2K 把几乎所有开关都做成输入关键字。
- 若你给 CP2K 提 PR 或改源码，这些是必须遵守的约定。

> 官方 CI 会检查这些（见 `18_performance_and_gpu.md` 的 dashboard：`Coding conventions ... Found 0 issues`）。
